# Практики Quint

> Как пишем и проверяем модели в этом репозитории. Перенесено из `transcriptor/quint/PRACTICES.md` (2026-10-25) —
> там же источники и разбор каждой практики. Добавлено: Р10 — развилка, Р11 — «когда-нибудь случится» через TLC,
> перечни вместо строк для фаз, `tools/show.py`.

## Обязательно — проверяет `npm run quint` (код выхода ≠ 0 при нарушении)

| # | Правило | Как проверяется |
|---|---|---|
| Р1 | Шапка: `// props:`, `// expect current:` (✅/❌ на каждое свойство), `// witnesses:`, `// mutants:` | нет строки / число не совпало — ⚠ |
| Р2 | Сценарии `…BugTest` на current и `…FixedTest` на fixed есть и проходят | имена печатаются, падение — ⚠ |
| Р3 | current даёт ровно то, что в `// expect current:`; fixed — все ✅ | расхождение — «← ждали» |
| Р4 | Нет тупиков: на ✅ все трассы длиной STEPS+1; законный конец — действие `stutter` | короче — ⚠ тупик |
| Р5 | Каждый witness в fixed случается (> 0 % трасс) — свойство держится не впустую | 0 % — ⚠ |
| Р6 | Свойство, которое current не нарушает, ломается мутантом `mut_<name>` (`const MUT: str`) | нет мутанта / не ломает — ⚠ |
| Р7 | Новая модель — из `quint/TEMPLATE.qnt` | ревью |
| Р8 | Призрак («чего хотел пользователь», «что реально снято») задаётся независимо от проверяемого поля | ревью; мутант ловит «верно по построению» |
| Р9 | Apalache перед готовностью требования: `npm run quint:verify` | `[ok]` обязателен |
| Р10 | 🔀 Нерешённый выбор — не прятать в `fixed`: варианты `opt_<name>`, свойства `// option props:`, ожидания `// expect opt_<name>:`. ❌ у варианта — его цена, не ошибка; обязательные свойства — ✅ в каждом варианте | таблица `🔀`, расхождение с ожиданием — ошибка |
| Р11 | ⏳ «Когда-нибудь случится» (файл собран, баг дошёл) — `temporal` с `weakFair(…)` на действия системы и явными допущениями об окружении (`eventually(always(net))`); строка `// temporal:`, мутант `// temporal mutants:`. `quint run` такое не проверяет — только TLC полным перебором | `VERIFY=1`: fixed `[ok]`, мутант `violation` |

## Как писать модель

- Одна модель — одна подсистема (`specs/<подсистема>.qnt`), мир маленький: 2–3 значения на домен.
- Разделы по порядку: «Мир» → «Состояние» → «Действия» → «Свойства» → «Свидетели» → «Сценарии», в конце модули
  `current`, `fixed`, `mut_*`, `opt_*`.
- Правка помечена кодом подсистемы (К, З, Э), стоит за `if (FIX …)`, рядом «было: …».
- Фазы и состояния — перечни (`type Phase = Live | Ended | Done`), не строки: опечатка в варианте не пройдёт.
  Константы вариантов (`MUT`, `MIX`, `START`) остаются строками — их задаёт импорт модуля.
- Окружение и отказы — отдельные действия: Wi-Fi, экран погас, вкладку выгрузили, сервер лёг.
- Свойство формулирует требование («снятое есть в файле»), а не пересказывает код («флаг выставлен»).
- `x' = (a or b)` — в скобках, иначе `or` склеит действие; каждая переменная — ровно раз за шаг.
- `current`, где функции ещё нет, держит свойство впустую — оговорить в шапке и дать мутанта.
- Призрак записывает, что было «в ту секунду», а не итог: свойство над логом по секундам не путает «до» и «после»
  (так ловится «нажал ▶ позже, а проверка смотрит на прошлые секунды»).
- Свойство упало на `fixed` — сначала трасса (`tools/show.py`): это дыра в требовании или в формулировке свойства?
  Дыра в требовании — в README «Что модели нашли», решение — человеку.
- Случайный перебор (`run`) пропускает редкие цепочки: `meetup_flow` — 20 000 трасс зелёные, а Apalache за 8 шагов
  нашёл Н15. Модель из нескольких подсистем — только вместе с `npm run quint:verify`.
- «Понятно ли и удобно ли» формулой не проверяется — в каталог с пометкой «нет», сверка с человеком.

## Порядок работы

```
требование → current → BugTest воспроизводит → fixed (правки за FIX) → мутанты на ✅ в current
  → npm run quint (0) → npm run quint:verify → каталог + README + спека → код → current = fixed

Не делаем пока: связь модели с кодом прогоном трасс (MBT, `--mbt` + тест, вызывающий настоящие обработчики) — кода
телефона и сервера ещё нет; начать с ним вместе.
```
